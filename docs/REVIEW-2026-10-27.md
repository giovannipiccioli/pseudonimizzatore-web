# Review and interface refresh — 27 October 2026

Reviewed the local `anonymizer` and companion `pseudonimizzatore_web` checkouts, including
the engine pipeline and edits contract, browser worker, document bridge, tests, and UI.
This is a focused code and usability review, not an exhaustive security audit.

## Architecture

The separation is useful and should stay: the Python engine detects evidence, resolves
identities, applies policy, renders once, and reports residual findings. The static web
page owns the review history and presentation; `bridge.py` adapts the engine's public
API, and the worker keeps Python off the main browser thread. Dependencies remain
self-hosted, and document processing remains local.

The redesign uses the neighbouring Tributar-IA frontend's white, graphite, deep blue,
brick red and yellow palette. It adds a useful empty state and bundled example,
collapsible review sections, distinct document controls, visible undo/redo, keyboard
access to highlights, and responsive layout. It adds no framework, build step, external
fonts, network service, or runtime dependency. The engine and its vendored wheel were
not changed.

## Existing issues found

### 1. Python offsets are used as JavaScript string offsets

`app.js`, `showDocument()` and `keepHere()`, slice strings using offsets returned by
Python. Python counts Unicode code points; JavaScript's `slice()` counts UTF-16 code
units. A character such as an emoji before a name shifts the displayed highlight.

Reproduction: `📄 Il sig. Mario Rossi ricorre.` returns a redaction at `[10, 21]`.
The JavaScript slice is ` Mario Ross`, while the intended text is `Mario Rossi`.
The engine's exported text is correct in this reproduction, but the displayed span
and the text recorded for a reviewer action are wrong.

Suggested follow-up: keep engine coordinates in code points, and convert only when
slicing for presentation. Add browser coverage for non-BMP characters in TXT and DOCX.

### 2. Partial-keep warnings miss the full-name-to-surname direction

`bridge.py`, `partial_keeps()`, warns only when the words of a kept span are a subset
of a remaining redaction. Keeping a full name while its surname remains redacted
therefore produces no warning, even though the two can still be linked.

Reproduction: analyse `Il sig. Ferruccio Malaspina ricorre. Il Malaspina insiste.`,
then keep only the full-name occurrence. The output becomes
`Il sig. Ferruccio Malaspina ricorre. Il Nominativo_1 insiste.`, but `partial_keeps`
is empty. Keeping the surname while redacting the full name does produce a warning.
This was reproduced both through the browser and directly through the bridge.

Suggested follow-up: relate keeps to the engine's entity aliases, with regression
cases for both directions and for unrelated people sharing a name token.

These issues predate the visual refresh and remain unchanged here.

## Validation

- Engine suite: **359 passed, 4 skipped, 16 expected failures**. Optional model tests
  were skipped when their dependencies or cached model were unavailable.
- Web bridge suite, including doctests: **36 passed**, using the vendored engine wheel.
- Fixture check: all **124** fixtures passed the real-name check.
- Current default corpus measurement: **472/488 complete entities (96.7%)**,
  **746/768 surfaces (97.1%)**, **111/124 complete documents**, **720/726 protected
  values kept**. The review heuristic flagged all 13 documents with missed entities,
  but also 107 documents without them. These are baseline limitations, not regressions
  from CSS or markup changes; manual review remains central to the product.
- Browser checks: bundled example, review dismissal, undo/redo, keyboard highlight
  actions, partial-keep warning in its supported direction, export confirmation,
  opening a DOCX, and TXT/DOCX downloads. Both downloaded files were inspected and
  contained two `Nominativo_1` tags in place of the two invented `Mario Rossi` names.
- Desktop and narrow layouts inspected; no horizontal page overflow in the checked
  narrow views. JavaScript syntax and Git whitespace checks passed.

The Python suite does not exercise browser interaction. A small browser smoke suite
covering the existing workflow would be the most useful next testing addition.
